## 3. 저장소 구조와 공통 모듈 사용법

저장소는 **앱마다 하나**이고, 각 저장소만 받아도 바로 빌드된다(제출 형태와 같음).

```
hyundaiapp-chachelin/            hyundaiapp-cruisebreaker/
├─ app/        이상준·길민종      ├─ app/        이민하·길민종
├─ core/       ◄── 원본 ──────►  ├─ core/       (복사본)
├─ tools/      ◄── 원본 ──────►  ├─ tools/      (복사본)
└─ docs/                          └─ docs/
   └─ team-collaboration-plan.md     └─ team-collaboration-plan.md (복사본)
```

**공통 부분 동기화 규칙**

1. 공통 부분은 `core/`, `tools/`, `docs/team-collaboration-plan.md`, `docs/handoff/README.md`, `docs/pr-review-guide.md`, `CLAUDE.md`, `.github/pull_request_template.md`다. **원본은 차슐랭 저장소**다.
2. `core/`는 황준용만 고친다. 다른 사람은 필요한 것을 황준용에게 요청한다. (GitHub 아이디가 정해지면 `.github/CODEOWNERS`로 건다.)
3. 고칠 때는 차슐랭에서 먼저 고치고 `core/VERSION`을 올린 뒤, 두 저장소를 나란히 받아 둔 상태에서 차슐랭 쪽에서 실행한다:
   ```
   tools/sync-core.sh ../CruiseBreaker            # 복사
   tools/sync-core.sh ../CruiseBreaker --check    # 같은지 확인만
   ```
   그다음 크루즈브레이커에도 같은 내용으로 PR을 올린다. PR 제목에 `core vX.Y.Z`를 적는다.
4. `--check`는 11-05 중간 점검과 11-12 제출 준비 때 장호연이 돌린다.

참고 문서 원본(`vehicle-data-findings.md` 등)은 팀 로컬 폴더 `hyundai-app/`에 있다. 각 앱의 `docs/`는 PRD 근거용 사본이며, 제출 전에 장호연이 원본과 맞춘다.

## 4. GitHub 운영 규칙

1. **Organization으로 이전**(황준용, 11-01까지): 지금은 개인 계정(`hoyeoni1`) 저장소라 심사용 계정을 Collaborator로 초대하면 쓰기 권한까지 넘어간다. Organization에서는 읽기 권한만 줄 수 있다.
2. **모든 변경은 PR로 올린다. 리뷰는 Claude, 머지는 장호연만 한다.**
   - 흐름: 브랜치에서 작업 → PR → **Claude 리뷰**(장호연 계정의 에이전트가 빌드·테스트·규칙을 확인하고 PR에 코멘트) → 작성자 수정 → **장호연 머지**
   - 작성자는 자기 PR을 머지하지 않는다. 에이전트도 머지하지 않는다.
   - 리뷰 기준: `docs/pr-review-guide.md`
   - 예외: 장호연의 기획서(`docs/proposal.md`, `docs/submission/`)는 `main`에 바로 push
3. 브랜치 이름: `feat/<짧은-설명>`, `fix/<...>`, `docs/<...>` (영문 소문자·하이픈. 한글 금지 — `CLAUDE.md` 규칙).
4. PR은 작게(하루 단위). PR 본문에 "에뮬레이터에서 확인한 방법"을 적는다(PR 템플릿).
5. 시연 영상·release APK는 `main`에서만 빌드한다.
6. **인수인계 문서 필수**: 작업을 마칠 때마다(사람·에이전트 모두) `docs/handoff/<영문-이름>.md`의 "현재 상태"를 덮어쓰고 "작업 기록"에 날짜 항목을 추가한다. PR에 이 수정이 없으면 Claude 리뷰에서 "수정 필요"로 돌려보내고 머지하지 않는다. 다음 사람이 문서만 읽고 이어서 일할 수 있어야 한다(양식: `docs/handoff/README.md`).
7. **각자 작업**: 자기 담당 경로(2절)와 자기 브랜치에서만 작업한다. 남의 경로는 담당자에게 요청한다.

## 7. 교차 읽기 (PT 기술 Q&A 대비)

리뷰·승인은 Claude와 장호연이 하지만, PT에서는 참가자가 코드를 직접 설명해야 한다. 그래서 아래 사람은 PR을 읽고 모르는 부분을 PR 코멘트로 질문한다(승인 권한 없음).

- 이상준 ↔ 이민하: 서로의 앱 로직 PR
- 황준용의 `core`·서버 PR: 이상준, 이민하
- 길민종의 UI PR: 해당 앱 담당
- 장호연의 도구·릴리스 PR: 황준용

모든 코드를 최소 2명이 설명할 수 있게 한다. PT 전주에는 앱마다 "구조 설명 리허설"을 1회 한다.

3. Pleos Connect 첫 탑재 차종에 전기차가 포함되는지
4. 심사용 GitHub 계정명
5. 시연 영상 길이·형식·제출 방법
6. DO(`distractionOptimized`) 선언만으로 앱마켓 배포본도 주행 중 화면이 허용되는지, 별도 심사 절차가 있는지 (10-30 "adb 설치본 차단" 관찰은 차슐랭 화면을 착각한 것으로 10-31 확인 — 에뮬레이터에서는 DO 선언 앱이 차단되지 않음)
7. 실차는 시동 off 때 헤드유닛이 완전히 꺼지는지, 절전(suspend)했다가 깨어나는지 — 절전이면 부팅 자동 시작이 안 걸림
