# 크루즈 해제 판정 규칙 v2 (2026-11-01, 이민하)

PRD 5.3 규칙을 이 문서로 바꾼다. PRD 반영은 장호연에게 요청(아래 "팀원별 요청").

## 무엇이 바뀌었나

| 항목 | 전 (PRD 5.3) | 후 |
|---|---|---|
| 해제 유형 | 브레이크 2초 안 → `BRAKE`, 아니면 `OTHER` | **없앰.** 상황 종류를 나누지 않는다 |
| 정체 제외 | 혼잡 구간 안이거나 30초 평균 < 40km/h면 버림 | **없앰.** 정체가 시작되는 곳도 위험으로 본다 |
| 칸 경계 | 칸마다 따로 셈 | 서버가 **둘레 8칸까지 9칸을 합쳐서** 판단 |
| 일시적 상황(공사) | 기간 제한 없음 | 최근 28일만 셈 |
| 안내 문구 | 유형별("합류 구간" 등) | 한 문장으로 통일 |
| `USER_OVERRIDE` | 해제로 셈(버그) | 작동 중으로 봄(가속 페달로 잠깐 덮어쓴 것, 해제 아님) |

**왜:** 기획의 핵심은 집단지성이다. 차는 사실만 기록하고, 위험한지는 여러 차의 비율로 정한다.
- 위치에 묶인 원인(급커브, 합류, 상습 정체 시작점, 공사)은 같은 곳에 쌓여 비율이 오른다.
- 우연한 원인(앞차 급제동, 센서 가림 등)은 여기저기 흩어져 비율이 오르지 않는다 → 따로 거를 필요 없음.
- 운전자가 할 일(주의, 감속 대비)은 원인과 상관없이 같다 → 안내도 나눌 필요 없음.

## 크루즈가 꺼지는 상황

| 상황 | 같은 곳에서 반복되나 |
|---|---|
| 급커브 | O |
| 합류나 끼어들기가 잦은 곳 | O |
| 상습 정체가 시작되는 지점 | O |
| 공사, 도로 파손 | O (일시적 → 28일 기간으로 자연히 사라짐) |
| 미끄러운 노면 | △ |
| 앞차 급제동, 긴급제동, 센서 가림, 핸들 놓음 경고 | X (흩어짐) |
| 오래 정차해서 자동 해제 | X (차속 조건으로 뺌) |

알고 쓰는 한계: IC 진출 직전에 크루즈를 끄는 곳도 위험 구간으로 잡힐 수 있다. 출구 구분은 하지 않기로 했다(11-01).

## 차 쪽 규칙 (이민하, `domain/`)

| 규칙 | 값 (초기값, 조정 가능) |
|---|---|
| 작동 중 | `ACTIVATED`, `USER_OVERRIDE`, `FORCED_DEACTIVATION_WARNING` |
| 해제 | 작동 중 → 그 밖의 값(`ENABLED`, `SUSPENDED`, `OTHER`, 없음). 에뮬레이터는 `ACTIVATED → ENABLED` |
| 해제로 세는 조건 | 작동 3초 이상 유지 뒤 해제 **그리고** 해제 순간 차속 ≥ 60km/h. 차속을 모르면(권한 없음) 속도 조건은 건너뜀 |
| 통과 | 작동 중에 새 구간(칸 + 방향)에 들어서면 1회. 작동을 시작한 구간도 1회. 해제한 구간은 반드시 통과도 기록됨 |
| 구간 ID | geohash 7자리(약 150m 격자) + 진행 방향 8방위. **원래 좌표는 서버로 보내지 않음** |
| 서버로 보내는 것 | 해제: 구간 ID, 시각(시간 단위로 내림), 가명 차량 ID. 통과: 구간 ID, 날짜, 가명 차량 ID |

## 서버 판단 (황준용, `segment_risk`)

| 규칙 | 값 |
|---|---|
| 합치는 범위 | 같은 방향(heading8)에서 그 칸 + 둘레 8칸 = 9칸 |
| 분모 | 9칸 중 한 곳이라도 크루즈로 지난 **차량-일 수**(가명 차량 ID와 날짜로 중복 제거) |
| 분자 | 9칸 안에서 해제한 차량-일 수 |
| 위험 구간 | 해제율 ≥ 30% **그리고** 분모 ≥ 20 |
| 기간 | 최근 28일(11-01 확정) |

- 중복 제거가 필요한 이유: 한 차가 9칸 중 3칸을 지나면 통과가 3번 잡혀 비율이 1/3로 묽어진다.
- 해제가 칸 경계에 몰려 있어도 어느 한 칸의 9칸 범위에는 다 들어가므로 경계 문제가 사라진다.
- 붙어 있는 칸들이 함께 위험으로 잡히는 것은 안내 쪽 "최소 3분 간격"으로 한 번만 안내된다.
- geohash 둘레 칸 계산은 앱 `domain/SegmentKey.kt`의 `neighbors()`와 같은 결과여야 한다(테스트 값 참고).

## 안내 (이민하, `RiskAnnouncer`)

| 규칙 | 값 |
|---|---|
| 언제 | **크루즈 작동 중일 때만**(11-01 결정) |
| 대상 | 진행 방향 ±30° 안, 앞 300~500m에 위험 구간 중심이 처음 들어올 때. 위험 구간의 방향(heading8)이 내 진행 방향과 45° 안 |
| 거리 | **500m 고정**(11-01 결정). 운전자가 바꾸지 않음 |
| 음성 | "500미터 앞, 크루즈 해제가 잦은 구간입니다." Pleos TTS SDK `ai.pleos.playground:TextToSpeech:3.3.1` 기기 내(`ON_DEVICE`) 모드, 언어 `ko_KR`. 퍼미션 `pleos.car.permission.TTS_SERVICE`(normal). 에뮬레이터에서 음성 재생 확인(11-01). Android 기본 TTS는 에뮬레이터에 엔진이 없어 실패 |
| 배너 | "500m 앞 크루즈 해제 잦은 구간" (한 줄, 10초 뒤 사라짐) |
| 제한 | 같은 구간은 한 주행에서 1회, 안내 사이 최소 3분 |
| 한 주행 | 기어 D로 출발 ~ P로 바뀔 때까지 |

## 업로드와 차량 ID (11-01 결정)

| 규칙 | 값 |
|---|---|
| 업로드 시점 | **실시간**: 해제·통과가 생길 때마다 바로 보냄. 실패하면 앱에 쌓아 두고 다음에 다시 보냄 |
| 가명 차량 ID | 앱 설치마다 무작위 UUID. 기기 정보·차대번호(VIN)·계정은 쓰지 않음. 앱을 지우면 새 ID |
| 보내는 형태 | 해제: 구간 ID·방향·시각(시간 단위)·가명 차량 ID. 통과: 구간 ID·방향·날짜(한국 시간)·가명 차량 ID. 좌표·차속은 앱 밖으로 안 나감(`DisengageUpload`·`PassUpload`) |
| 동의 철회 | S4 [동의 철회] → 기록·안내·신호 수신 즉시 중지, 기기의 동의·가명 차량 ID·주행 요약 삭제. 다시 동의하면 새 ID. **서버에 올라간 기록 삭제 방식은 황준용과 정할 것**(이슈 #7) |
