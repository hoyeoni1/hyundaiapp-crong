# 시연 영상 시나리오 — 크롱 · 차슐랭 (v4.1, 2026-11-13)

앱 동작 순서는 확정 시연 시나리오([demo-scenario.md](demo-scenario.md))를 따른다. 이 문서는 **블렌더 상황 영상과 실제 구동 녹화를 어떤 순서로 잇는지**를 정한다.

두 앱이 한 문서를 같이 쓴다(크롱·차슐랭 저장소에 같은 내용). 블렌더 장면 파일과 렌더·녹화 결과는 용량 때문에 저장소 밖 작업 폴더 `demo-video/`에 둔다(이민하 PC).

## 1. 형식

| 항목 | 정한 것 |
|---|---|
| 편수 | 앱마다 1편 |
| 주인공 차 | 두 편 모두 같은 골드 아이오닉5 |
| 화면 | 1920×1080, 30fps |
| 소리 | 내레이션 없음. 앱 음성 안내(TTS)와 차량 알림음만 |
| 자막 | **넣지 않는다.** 블렌더에도 녹화에도 없다. 블렌더는 장면 안의 상황 표시 글씨만 쓴다('크루즈 해제', '500m', '충전 중', '충전 안 됨' 등) |
| 카드 | 시작 카드와 엔드카드 약 3초씩. **앱 이름과 팀 이름만** 넣는다(설명 문장 없음). 크롱 시작 카드만 "크롱 / CRONG / Cruise Risk Observation & Navigation Guide"까지 적는다. 글꼴 Pretendard |

전환 규칙

| 전환 | 방법 |
|---|---|
| 블렌더 → 녹화 | **항상** 블렌더 안에서 카메라가 인포테인먼트 화면으로 들어가 화면이 프레임을 채운 뒤 녹화로 넘어간다. 카메라는 그 컷에서 있던 자리에서 **한 직선으로** 들어간다(차 뒤로 돌아가는 등 자리를 다시 잡지 않는다) |
| 크기 | 진입이 끝난 화면과 녹화 첫 화면의 크기·위치가 같아야 한다. 블렌더 속 화면에는 이어질 녹화 구간의 첫 프레임을 붙이고, 카메라는 화면 폭이 프레임 폭과 정확히 같은 거리에서 멈춘다 |
| 녹화 → 블렌더 | 바로 컷 |
| 횟수 | 편당 블렌더 → 녹화 3번 |
| 겹침 | 없음. 블렌더 구간은 블렌더만, 녹화 구간은 에뮬레이터 화면만 |

녹화에서 담는 영역 (에뮬레이터 화면 2560×1440)

| 부분 | 위치 | 처리 |
|---|---|---|
| 왼쪽 계기판 패널(속도·기어) | x 0~853 | 잘림 없이 담는다 |
| 앱 창 | x 854~2533, y 91~1299 | 잘림 없이 담는다 |
| 아래 독 | y 1300~1439 | 잘림 없이 담는다 |
| 오른쪽 가는 흰 띠 | x 2534~2559 | 잘라 낸다 |
| 앱 위 상태 표시줄 | x 854~, y 0~90 | 앱 창 맨 윗줄 색을 위로 이어 덮는다(앱 화면이면 어두운 바탕, 내비면 지도 바탕) |

늘이거나 자르지 않고 0.75배로 줄인다. 폭이 20px 모자라는 만큼은 왼쪽 계기판 바탕을 이어 붙인다.

배속 규칙

| 구간 | 규칙 |
|---|---|
| 기다리는 구간 | 빨리 감는다. 해당하는 곳은 셋뿐이다: 충전 중 SoC가 오르는 동안, 충전 실패 대기(시간만 흐르고 SoC는 그대로), 크롱 배너가 떠 있는 동안 |
| 화면을 누르고 넘어가는 부분 | 빨리 감지 않는다. 원래 속도로 두고 사이의 멈춘 시간만 잘라 낸다 |

## 2. 크롱

한 줄 요약: **여러 차가 크루즈를 끈 곳을 모아, 다음 차에게 500m 앞에서 알려 준다.**

| 순서 | 구분 | ID | 내용 |
|---|---|---|---|
| 1 | 카드 | — | 크롱 / CRONG / Cruise Risk Observation & Navigation Guide / 팀 삼각고래 |
| 2 | 블렌더 | `KB1` | **커브 구간**에서 차들이 차례로 제동, '크루즈 해제' 표시와 핀이 쌓이고 구간이 붉어짐 → **합류 구간**에서 같은 일 → 길가 주차장의 골드 아이오닉5(출발 전) → **인포테인먼트 진입** |
| 3 | 녹화 | `KR1` | 첫 실행 동의 2개 + [시작하기] → 근처 해제 다발 구간 목록 4곳(가까운 순). 맨 위 판교JC 합류부 0.4 km · 해제율 40% · 500 차량·일 |
| 4 | 블렌더 | `KB2` | 크루즈 100km/h 주행(계기판 CRUISE 100), 앞쪽 붉은 구간까지 '500m' 표시 → **인포테인먼트 진입** |
| 5 | 녹화 | `KR2` | 내비 위로 앱이 올라오며 주황 배너 "500m 앞 크루즈 해제 잦은 구간" + 음성 → 내비로 자동 복귀 |
| 6 | 블렌더 | `KB3c` | 보통 주차장에 주차(계기판 P) → **인포테인먼트 진입** |
| 7 | 녹화 | `KR3` | 내비 위로 앱이 다시 올라오며 최근 주행 요약: 안내 1회 · 1곳 · 내가 보탠 기록 1건 → [해제 다발 구간 목록으로] |
| 8 | 카드 | — | 크롱 / 팀 삼각고래 |

- 해제 조건 시연(90km/h 해제는 기록, 40km/h 해제는 기록 안 함)은 영상에서 뺐다. 앱이 하는 일은 해제를 기록하고 안내하는 것이고, 조건까지 넣으면 복잡해진다. 녹화 스크립트는 확정 시나리오대로 두 번 해제하지만 그 사이는 내비만 보이므로 잘라 낸다.
- `KR2`와 `KR3`은 주행 녹화 한 번(`drive.mp4`)의 앞·뒤 부분이다(내비를 앞에 두고 시작).
- 동의 직후 목록은 위치를 아직 못 받아 "거리 확인 중"으로 뜬다. 녹화 스크립트가 설정에 다녀와 가까운 순 + 거리로 바뀐 목록을 찍으므로, `KR1`은 그 사이(설정 화면)를 잘라 쓴다.
- `KR2`는 계기판이 100km/h 주행 화면으로 바뀐 뒤부터 쓴다.

## 3. 차슐랭

한 줄 요약: **충전 결과를 차가 직접 기록하고, 실제로 충전한 사람만 평가한다. 실패도 차가 기록한다.**

충전 장면이 먼저, 충전소 고르기가 나중이다. 에뮬레이터 위치가 고정이라 충전은 항상 "시흥동 주민센터"로 잡히므로, 다른 곳으로 길안내한 뒤 충전하면 이름이 어긋난다.

| 순서 | 구분 | ID | 내용 |
|---|---|---|---|
| 1 | 카드 | — | 차슐랭 / 팀 삼각고래 |
| 2 | 블렌더 | `CB1` | 충전소(간판 '전기차 충전소')와 주차 칸의 골드 아이오닉5를 뒤에서 천천히 다가가며 보여 줌 → **인포테인먼트 진입** |
| 3 | 녹화 | `CR1` | 첫 실행 동의 2개 + 차종 "아이오닉 5" + [시작하기] → 홈 |
| 4 | 블렌더 | `CB2` | 한 자리에서: 충전구가 열리고 케이블 연결, 빛이 흐름, '충전 중' 표시 → **인포테인먼트 진입** |
| 5 | 녹화 | `CR2` | "충전 기록 중"이 저절로 뜸 → 40→80%(빨리 감기) → "인증 충전 완료" → 별 5개 + 태그 2개 + [평가 보내기] → 홈 "내 충전 기록 1건 · 인증" |
| 6 | 블렌더 | `CB3` | 같은 자리, 저녁(다른 날). 케이블을 꽂았는데 빛이 없음, 충전기 빨간 불, '충전 안 됨' 표시, 배터리 40%(케이블은 꽂힌 채) → **인포테인먼트 진입** |
| 7 | 녹화 | `CR3` | "충전 기록 중" — 경과 시간은 오르는데 40% 그대로(빨리 감기) → 충전구 닫힘 → "충전 실패를 기록했어요" → 홈 "내 충전 기록 2건 · 실패" → 내 기록 → 점수순 목록 → 시흥동 주민센터 상세(최근 실패에 방금 시각) → 대왕판교IC 휴게소 상세(별점은 대부분 5점인데 점수 최하위) → 1위 판교 테크노밸리 E-pit 상세 → [길안내] → 내비 경로 |
| 8 | 블렌더 | `CB4` | 고정 화면: 차가 주차 칸에서 나와 충전소를 떠남 |
| 9 | 카드 | — | 차슐랭 / 팀 삼각고래 |

- 충전 실패 대기 35초는 그대로 녹화하고 편집에서 8배속으로 줄인다. 블렌더 `CB3`은 케이블이 꽂힌 채로 화면에 들어가고, 충전구가 닫히는 것은 녹화에서 일어난다.
- 카메라는 컷마다 느린 움직임 하나만 쓴다. 차 주위를 돌거나 자리를 옮기지 않는다.

|---|---|---|---|
| `KB1` | 커브 구간 해제 누적 → 합류 구간 해제 누적 → 길가 주차장의 아이오닉5 | '크루즈 해제' | `assets/crong_consent.png` |

| `CB4` | 충전소를 떠남 | — | — |

- 화면 그림은 이어지는 녹화 구간의 첫 프레임을 녹화에서 뽑아, 녹화와 똑같은 방식(1절 "녹화에서 담는 영역")으로 만든 1920×1080 그림이다.

- `KB3a`(끼어들기 해제)·`KB3b`(정체 해제) 컷은 장면 파일에 남아 있지만 쓰지 않는다.

## 5. 영상 밖에서 밝힐 것

자막과 카드의 설명 문장을 모두 뺐기 때문에 아래 내용은 **영상 안에 나오지 않는다.** 제출할 때 영상 설명이나 기획서·PT에서 밝힌다.

| 편 | 내용 |
|---|---|
| 공통 | Pleos 에뮬레이터 실제 동작 녹화. 기다리는 구간은 빨리 감음 |
| 크롱 | 위치는 에뮬레이터 고정 위치, 해제 다발 구간과 다른 차량 기록은 시드 데이터. 크루즈 작동·해제는 에뮬레이터 값으로 대신함 |
| 차슐랭 | SoC는 콘솔 주입, 충전 시간과 kW는 시연 배속 ×120, 판정 기준은 시연용(인증 10초·실패 30초). 충전소와 다른 차량 기록은 시드 데이터 |

## 6. 만드는 방법

| 순서 | 무엇 | 어떻게 |
|---|---|---|
| 1 | 녹화 | 저장소에서 `bash tools/demo-video.sh crong`, `bash tools/demo-video.sh chachelin`. 화면 조작·차량 값 주입·녹화·주입 시각 기록(`events.tsv`)을 한 번에 하고, 끝나면 동의를 철회해 서버에 올린 기록을 지운다 |
| 2 | 소리 | 화면 녹화(`adb screenrecord`)에는 소리가 없다. 크롱 녹화를 돌리는 동안 `demo-video/tools/record-audio.ps1`로 PC 소리를 같이 녹음하고, `events.tsv`의 "녹화 시작" PC 시각과 녹음 시작 시각(`.start` 파일)의 차이만큼 밀어 `drive_av.mp4`로 합친다 |
| 3 | 화면 그림 | `python demo-video/tools/assemble.py crong assets`, `… chachelin assets` |
| 4 | 블렌더 | `demo-video/cruisebreaker/build_cuts.py`, `demo-video/chachelin/build_cuts.py` 를 컷마다 `-- <컷> anim res 1920` |
| 5 | 이어 붙이기 | `python demo-video/tools/assemble.py crong`, `… chachelin` → `demo-video/out/*.mp4` |

## 7. 녹화에서 쓰는 구간

시각은 그 실행의 `events.tsv`에서 읽는다. 영상 속 시각은 `events.tsv`의 초보다 약 0.9초 늦다(녹화가 기록 시작보다 먼저 돌기 시작함).

| 구간 | 파일 | 쓰는 부분 | 편집 |
|---|---|---|---|
| `KR1` | `crong/kr1.mp4` | 동의 화면 → 누르는 순간 3번 → 설정에서 돌아온 뒤의 목록 | 멈춘 시간과 설정 화면을 자른다. 배속 없음 |
| `KR2` | `crong/drive_av.mp4`(소리 합친 것) | 크루즈 작동 0.3초 전 ~ 배너가 사라지고 내비로 돌아올 때까지 | 음성이 끝난 뒤 배너가 떠 있는 동안만 3배속 |
| `KR3` | `crong/drive_av.mp4` | 기어 P 직후 ~ 요약 5초, 목록으로 돌아온 뒤 4초 | 배속 없음 |
| `CR1` | `chachelin/cr1.mp4` | 동의 화면 → 누르는 순간 4번 → 홈 | 멈춘 시간을 자른다. 배속 없음 |
| `CR2` | `chachelin/cr2.mp4` | 충전구 열림 ~ 홈 1건 | SoC가 오르는 동안만 6배속. 별점·태그는 누르는 순간만 이어 붙임 |
| `CR3` | `chachelin/cr3.mp4` | 충전 기록 중(40%) ~ 내비 경로 | 실패 대기만 8배속. 그 뒤 화면들은 누르는 순간부터 2~3초씩, 배속 없음 |
