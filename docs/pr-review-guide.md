# PR 리뷰 기준

- **리뷰**: Claude. 장호연 계정의 에이전트가 PR을 받아 확인하고, PR에 코멘트를 남긴다.
- **머지**: 장호연만 한다. 작성자와 에이전트는 머지하지 않는다.
- 이 문서는 두 저장소에 똑같이 들어 있다(원본: 차슐랭, `tools/sync-core.sh`로 복사).

## 리뷰 결과 표시

PR 코멘트 첫 줄에 셋 중 하나를 쓴다.

- `✅ 머지 가능`: 장호연이 머지하면 된다.
- `🔧 수정 필요`: 아래 "반드시 고칠 것"을 고치고 같은 PR에 다시 push한다. Claude가 다시 본다.
- `❓ 장호연 판단 필요`: 기획·범위·담당 경계 문제라 팀장 결정이 필요하다.

## 확인 항목

### 반드시 (하나라도 어기면 🔧)

1. **빌드·테스트 통과**: PR 브랜치에서 `./gradlew assembleDebug test`
2. **인수인계 문서 갱신**: `docs/handoff/<영문-이름>.md`의 "현재 상태"를 덮어쓰고 "작업 기록"에 날짜 항목을 추가했는지
3. **담당 경로**: 작성자 담당 경로만 고쳤는지(팀 문서 2절). `core/`는 황준용만 고칠 수 있고, 차슐랭에서 고친 뒤 `sync-core.sh`로 복사해야 한다
4. **이름 규칙**: 파일·폴더·브랜치 이름에 한글이 없는지(`CLAUDE.md`)
5. **퍼미션**: 새 퍼미션이 있으면 PR에 이유가 있는지, `AndroidManifest.xml`과 `AppContainer`의 `CoreFeature`가 맞는지
6. **비밀값**: API 키·서명 키·`local.properties`·apk가 커밋되지 않았는지(`apk/`의 release APK 제외)

### 코드 (중요한 것만 지적)

- PRD 규칙(판정 기준값 등)과 구현이 맞는지
- 크래시 가능성: null 처리, 메인 스레드 블로킹, 실행되는 경로에 남은 `TODO()`
- 화면은 UiState와 콜백만 받는지(ViewModel·SDK 직접 참조 금지)
- 크롱 주행 중 화면(S1): 터치 요소·애니메이션·여러 줄 텍스트 금지
- 로직에 단위 테스트가 있는지(`FakeVehicleSignals`)
- 서버로 보내는 데이터에 원래 좌표나 차량 식별자가 들어가지 않는지(PRD 5.5·5.6)

### 참고로만

- 이름·구조 개선 제안은 "선택"으로 표시하고 머지를 막지 않는다
